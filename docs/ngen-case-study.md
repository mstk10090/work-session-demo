# N限 — 事業とプロダクト開発の経験

大学生が短時間の仕事を通じて実務経験を得て、キャリアを考えるためのサービス。
立ち上げに関わり、Webプロダクトの開発に加えて、集客・運営・指標に基づく改善にも取り組んできました。

このページは開発経験を紹介するものです。本番コード、利用者の情報、顧客情報、非公開の事業指標は掲載していません。

## 向き合った課題

学生には、応募前に仕事の内容を理解し、自分が取り組めるかを判断するための情報が必要でした。
企業・運営側には、応募後のやり取りや進捗、成果物、評価を一連の流れとして扱う仕組みが必要でした。

機能単位の実装だけでなく、「その画面の後で、誰が何をするか」を整理することが重要でした。

## 関わった範囲

| 領域             | 内容                                                                           |
| ---------------- | ------------------------------------------------------------------------------ |
| プロダクト開発   | 学生・企業・管理者向け画面、案件応募、作業ログ、評価・候補者レポートなどの開発 |
| 課題・要件の整理 | 学生や企業のニーズを踏まえた機能・業務フローの検討                             |
| 運営・チーム     | 登録・応募などの指標の具体化、チームで施策を検討するための認識合わせ           |
| 集客と改善       | SNSなどから登録・初回参加に至る導線の検討                                      |

開発には生成AIを活用しています。チームで進めた業務を含むため、全機能を一人で手書きした実績としては紹介していません。

## 技術的な構成

Next.js / React / TypeScriptを中心に、Prisma / PostgreSQLによるデータ管理や、認証・通知などを組み合わせたWebサービスです。

- 学生・企業・管理者の役割ごとに画面と操作を整理。
- APIでリクエストを受け、共通の業務処理を呼び出す構成。
- 応募から作業・成果物・評価へつながるデータを管理。

これはシステム全体の構成の説明であり、全領域の設計・品質が完成しているという主張ではありません。

## 学び

### 機能を増やす前に、目的と次の行動を決める

学生向けの体験、企業側のニーズ、運営上の都合を同時に考える必要がありました。
誰のどの課題を解くのかを具体化すると、機能の優先順位を議論しやすくなりました。

### 実装したことと、価値が生まれたことを分ける

画面が完成しても、利用者が次の行動に進むとは限りません。
登録や応募などの指標を整理し、開発後の利用状況をもとに改善を検討する姿勢を重視しました。

### 変更しやすさも、プロダクトを続けるための要件

仕様が変わる中では、業務ルールと画面の分離、変更箇所の集約、境界条件のテストが重要です。
公開サンプルではこの点に焦点を当て、予約可否の判定を純粋関数として切り出しています。

## 公開サンプルとの関係

[Work Session](../README.md)は、短時間の仕事に参加する場面を題材にした新規のデモです。
N限の本番機能を再現したものではなく、過去の利用者数や改善効果を示すものでもありません。

見ていただきたいのは、課題から仕様を絞り込み、画面・業務ルール・テストまでつなげる考え方です。
